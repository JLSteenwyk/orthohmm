# Native Candidate Order/Score Diagnostic

Before inspecting the new diagnostic outcomes, fix these five arms in order:
historical order/historical scores, historical order/fresh scores, fresh
order/historical scores, fresh order/fresh scores, and full fresh hits with
self hits. Use the original seed bytes/order, original satellite_v2 parameter
dictionary and pinned frozen refinement function in every arm. Only the
declared hit order, values and self-hit inclusion differ. One attempt per
arm; retain failures and all partial outputs, with no retry/resume.

The new driver reuses the existing factorial alignment helper. Require
identical unique directed nonself pair sets, identical gene indexing and a
bijection of species memberships. Pin the trusted local historical pickle
before loading it. Pin every file of the independently validated native
checkpoint and both full candidate partitions through the retained score.
Prepare a source/input/runtime-bound plan before executing any real arm.

Execute the original frozen candidate-expansion function directly, not an
installed replacement or reimplemented search algorithm. Save every complete
partition, accepted merge trace and per-arm count. Compare every pair of arms
and require the historical and full-fresh controls to reproduce their
respective whole partitions. A mismatch remains a failed diagnostic with
all results, not a reason to silently alter seeds or input values.

This is a fixed-seed candidate-stage diagnostic. Even successful controls
do not establish the entire original search's score-bit provenance, universal
determinism or exact fresh pre-expansion seed order. The original seeds are
already known to suffice for accepted-trace reconstruction. Do not tune
assignments, round values, select a matching arm, change defaults, infer
accuracy gains, perform phylogeny or score the benchmark during this probe.

Use the matching Python3.10/NumPy2.2.6 review environment with BLAS/OpenMP
threads1. Bind the interpreter, NumPy initializer/native extension and frozen
source; these bindings are not a full dynamic runtime closure. Check safe
memory capacity before this local diagnostic. Restrict only its own CPU
affinity, leaving the32-CPU native22430 allocation and unrelated analyses
untouched. Its observed duration is diagnostic-only, not comparative timing.
Shared-host CPU/memory/I/O competition remains accepted and monitored;
unknown, potentially tool-dependent distortion is not corrected away.

CLI: `probe_native_candidate_order_scores.py --preparation PATH
--preparation-sha256 SHA --score PATH --score-sha256 SHA --output FRESH_DIR`,
then `--run FRESH_DIR/plan.json --plan-sha256 SHA`. Preparation cannot execute
the scientific arms, launch Slurm jobs, score, release or modify existing runs.
Do not edit its source after producing a bound plan. Actual terminal review
and separate score of22430 still precede the next native identity.
