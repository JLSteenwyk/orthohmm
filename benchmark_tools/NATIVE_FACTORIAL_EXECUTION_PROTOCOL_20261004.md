# Full Native Factorial Execution Handoff

This prospectively extends the [thirteen-identity protocol](NATIVE_FACTORIAL_COST_PROTOCOL_20261004.md),
not the closed27-attempt scaling panel. The eight native fixtures and job22380
accounting/cadence calibration are reused subject to their unchanged bindings.
No method default, original factorial cost field or selected score is changed.

The separate executor reserves64 Slurm slots/128GiB on bizon, with native
affinity to32 distinct physical cores0-31, 8 search workers/4 threads,
85,800s native timeout and26h allocation. No requeue, node exclusivity,
automatic next submission or implicit retry. Each prospective index gets
one explicit held-job request pinned by its scheduler comment. Previous
identities must be terminal and individually reviewed before advancing.

Each attempt copies the exact pinned FASTAs into its fresh persistent output
directory before native inference. This differs from the historical scaling
panel's tmpfs copies and deliberately fixes a new, disclosed storage scope
for all thirteen new identities. Basename creation is sorted. Native
enumeration is frozen using a same-filesystem empty-filename fixture, then
checked by executing the frozen enumerator on the actual copied inputs; an order mismatch
fails the attempt without inference or an automatic second copy. Record
header-order gene ownership/per-species counts and preserve every copy.
This is not an exact historical input-order replication or cold-cache test.
The original and copied inputs are hashed before/after inference. Hashing,
copying, gene-ownership validation and native runtime smoke checks are
outside the native timer and their preparation/check durations are retained.

The benchmark-only adapter changes only downstream profile expansion for
P-off and the candidate reconciliation gate for C1R0. All eight factor
settings use the frozen sensitive initial HMM search, BLOSUM62/E1e-4,
LeidenCPM0.1/seed4 and default refinement. C/R parameters remain unchanged.
R infers fresh species/family trees; there is no historical checkpoint input.
Production source/globals/defaults remain unchanged. Native receipt includes
factors, actual enumeration, stages and counts; exact output/accuracy review
and conversion remain separate from process exit success.

Reuse the unchanged Threadripper collector, lifetime native-step memory peak,
native subtree CPU-stat bracket, monotonic launch-to-exit interval and
30s typed foreign-process/1s native pressure/affinity observations. Fresh
Numba/TMP and absent bytecode cache prefixes are used. Native wall includes
private interpreter startup, adapter/import/placement verification and its
small terminal receipt, not controller input/runtime hashing or conversion.
These wrapper costs are not subtracted. Native/job memory peaks overlap;
do not add them. Whole-job teardown totals remain unavailable.

The actual launch guard checks the parked native worker's validated scope,
compares typed same-boot host process snapshots, records raw host counters,
PSI/meminfo and validates the current26h scheduler budget and request hash.
At least128GiB MemAvailable is required at launch, following the retained
shared-host capacity policy. This is not a guarantee against later pressure.
Ordinary background CPU, PSI magnitudes and outside process churn are
diagnostics, not quiet-window gates. Process attribution/read integrity,
resource/accounting validity and unsafe capacity can fail a launch.

The post-run process/pressure audit replays the entire sampled stream against
the reused shared-host process policy. Independent terminal scheduler,
source/runtime, output/checkpoint, CPU/memory/affinity and cadence reviews
are still required; a passed wrapper does not authorize the next index.
Retain all failed/timed-out/unreviewable outcomes without overwriting them.

Timing tables, figures and Methods must disclose competing analyses and an
unknown, potentially method-dependent distortion. No claim of isolated
performance, corrected elapsed time, causal component overhead or definitive
speed ranking is supported. Compare partitions before associating old
accuracy claims, preserving all differences rather than selecting matching
outputs. Historical deployments, resource definitions and tmpfs/persistent
storage scopes are not pooled into a matched causal comparison.
