# Native Frontier Integration Protocol

Purpose: observe outside-job cgroup CPU changes contemporaneously with the
unchanged native-step screen. Earlier read-only frontier observations do
not explain the retained satellite_v2 interval flag, and repeated old
instrumentation cannot resolve that attribution question.

The new collector is separate from all frozen interval/hierarchy collectors.
Each point retains the original hierarchy read, then samples a disjoint
cgroup frontier targeting the current job parent, then closes an expanded
host bracket. The original intermediate host snapshot is retained too.
Validate target/boot identity, counter monotonicity, stable frontier inodes,
and temporal enclosure. Recheck native PID membership after collection.

Use the existing complete-command handshake, final memory observation and
worker cleanup lifecycle unchanged. Original threshold calculations use
the same native-step reads with the expanded host brackets. Frontier
differences are an additional descriptive output, never a subtraction from
the native timing screen. The two counter systems have different windows;
they must not be presented as synchronized attribution. No positive or
negative residual is silently discarded.

## Required Native Check

Before any scientific scaling rerun, perform one complete three-method
engineering array on the retained645-protein/8-species fixture, with exactly
the previously frozen native commands and20CPU/96GiB exclusive allocations.
Run high-sensitivity, satellite_v2 and full OrthoFinder sequentially. Finish
all transfers before submission, delay eligibility by at least60seconds,
then perform no DGX remote calls until local scheduler evidence shows all
tasks terminal. Retain every task, failure and flag; no selective repeat.

Verify transferred sources, input/runtime identity and native outputs,
archive all raw point records, and replay both original screens and frontier
arithmetic locally. Changed topology or unreadable counters invalidate the
observation rather than producing zero usage. Report these failures without
an automatic retry. Existing flags and scientific timing admission rules do
not change if more outside-scope accounting becomes visible.

## Scope And Outstanding Gates

This protocol does not authorize the27-run scientific scaling panel.
Native collector overhead, non-CPU interference, and a scientifically
defensible inclusion policy remain separate requirements. Current work
provides a tested collector only; launcher/recipe verification and native
execution must still occur before any integration result is claimed.
