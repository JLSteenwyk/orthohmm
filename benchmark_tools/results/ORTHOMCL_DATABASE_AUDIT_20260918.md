# OrthoMCL Formatted Database Audit

## Component

`audit_orthomcl_database.py` uses the legacy `fastacmd -p T -D 1` extractor
bound to the frozen BLAST 2.2.13 runtime manifest. It verifies that runtime
before and after extraction, records database/input/helper hashes, rejects
configuration overrides, and uses a fresh output directory and clean process
environment. Extraction failures or unexpected stderr are retained as failed
reports, not silently accepted.

The supported layout is exactly the three nonempty unsplit protein database
files (`.phr`, `.pin`, `.psq`) generated by the frozen default `formatdb`
command. Symlinks, aliases, split databases and extra prefix-matching files
require separate review rather than implicit acceptance.

Every extracted record is compared in order with the combined FASTA. The
expected `gnl|BL_ORD_ID|<ordinal>` prefix and original description must match;
unknown/reordered/missing/extra records and duplicate input IDs fail. Sequence
lengths and case-sensitive SHA-256 values are compared without normalization.
Differences produce `database_sequence_differences_require_review`, not an
exact-parity claim. The extracted FASTA and diagnostic log remain available.

The second tiny probe demonstrated native behavior worth retaining: input
`MABZXU*` was extracted as `MABZXU`, and `macdefghik` as `MACDEFGHIK`.
The canonical uppercase sequence was unchanged. This observation is limited
to the fixture; it is not evidence that corrected benchmark sequences undergo
these changes, nor permission to normalize their differences away.

## Remaining Production Gate

Corrected search job 21713 is still resource-pending. Its terminal execution
report and before/after database inventory must be authenticated before using
this component on production output. Database parity and table/query auditing
then need to be integrated into one search-admission report. BPO/index
validation and native final-group inference remain separate unfinished stages.

All component reports deliberately retain `database_admitted: false`,
`search_admitted: false`, `accuracy_admitted: false` and
`publication_ready: false`, including when the extraction matches exactly.
Exact current database content alone does not prove which bytes a historical
BLAST process used, complete query processing, or downstream correctness.
