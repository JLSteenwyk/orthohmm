# Composed Native QfO Scientific Reporting

`export_composed_native_qfo_scientific_scores.py` is a prospective reporting
successor, not another scientific admission. It pins and preserves the frozen
four-cell snapshot `native_qfo_scientific_scores_20261007_v3/report.json`, including
the recovered-science row's failed-timing status and null resource eligibility.
The original exporter, manuscript v4, figures and archival bundle remain unchanged.

The explicit native11 failure addendum supplies reviewed inference/conversion
coverage and an OUT_OF_MEMORY scoring outcome. That row has six null endpoint
scores and a null secondary mean. Five completed endpoint tasks do not become
five admitted scores, a partial six-metric mean or a zero FAS value.

A final native12 row is optional only to allow truthful missing-data reporting.
To supply it, use its actual independently admitted result in the separate
`native12_composed_qfo_admission_v1` namespace. Recheck exact new admission,
conversion, request, reviewer and scientific-output identities/source records;
native reconciled-pair semantics and reviewed row count; full-input coverage;
selected native CPU IDs; scoring preflight/spec/namespace/resource allocation;
successful producer accounting metadata; FAS membership audit; and original
six-endpoint arithmetic. The actual request digest remains pinned. No original
schema is invented. Direct report/source checks do not repeat raw inference,
scoring or full transitive scientific admission.

The output JSON, TSV and Markdown retain all seven planned QfO identities. The
four admitted historical rows remain exactly equal to the baseline. Unavailable
and failed rows remain distinct from admitted rows. GO/EC/FAS are not labelled
F1; the six-metric mean is a project-defined secondary summary. Inference and
scoring resource scopes remain separate; prospective final scoring uses 128 GiB
without changing the native inference allocation or implying isolated speed.

CLI: `--output` requires a fresh successor directory. `--final-admission PATH
SHA256` may be supplied only after actual independent admission. Implementation
tests exercise real endpoint arithmetic and new explicit metadata with synthetic
review/scheduler context. They supply no production score. No successor score
export has been executed while native inference remains running.

Family uncertainty is not attached automatically. The eventual final SwissTrees
raw file must be audited with the unchanged family-count kernel and the complete
retained reference. Old intervals may be reused only when every family record
and aggregate is identical, never merely because global F1 agrees. Changed counts
require appropriate new paired analysis or explicit unavailable intervals; failed
native11 scoring supplies no family counts or imputed contrasts. Development
exposure, family exchangeability and multiplicity limitations remain intact.
