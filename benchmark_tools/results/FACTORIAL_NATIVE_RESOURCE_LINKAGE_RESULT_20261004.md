## Evidence And Scope

The reader verifies the fixed original OrthoBench preparation/results, final
shared-host panel and native plan. It checks all twelve original FASTA bytes
and 251,378 unique identifiers, 38 frozen core source identities, both original
prediction partitions and the 70 reference files. Every selected run has the
same original FASTA descriptors, prescribed high-sensitivity settings and
complete native stages. Reconciliation settings and satellite parameters match
the original arm; native reconciliation/species-tree checkpoint hits are zero.

Retained environment, resource, runtime and output reviews are pinned by the
final panel and pass. Intermediate summaries are checked against those reviews
and the panel's resource/contention fields; the panel does not directly pin
every intermediate summary. The new report records 173 direct input identities
and rechecks them before writing. It does not repeat the earlier raw forensic
audits or certify every transitive binary again.

All three high-sensitivity final partitions equal the original `p1_c0_r0`
partition, independent of group names and ordering. Phylogenetic `p1_c1_r1`
repeat 0 matches the original final partition; repeats 1 and 2 have respectively
two and four original-only groups, with the same numbers of replacement groups.
Those changed groups contain 149 and 172 genes. This is the number of genes
in affected groups, not the number of individual genes moved.

All three phylogenetic candidate partitions differ from the original candidate
partition: 10, 2 and 14 original-only groups, involving 70, 160 and 253 genes in
affected groups. Counts and prescribed parameters alone would have missed this.
No changed candidate or final group intersects any of the 70 reference families;
the complete reference-touching final groups remain identical. This structural
check is not a new accuracy calculation. No cause of the differences or equality
of native pair files, trees or alignments has been established.

These are shared-host observations with unknown, potentially method-dependent
contention. They do not establish isolated speed rankings or causal component
overhead. The native launch-to-exit timer includes inference and native metrics/
output writing, but not input preparation, harness hashing, external conversion
or scoring. CPU includes wrapper-bracket work; lifetime cgroup memory peak
includes the launcher. Do not mix it with historical sampled tree RSS.

The patched private Python runtime differs from the original factorial
deployment. These observations describe the prescribed native configurations
on the original inputs, not timings of the original cached executions or exact
reproduction of every intermediate/output. Fourteen other factorial
configurations remain without associated full-native costs in this report.
