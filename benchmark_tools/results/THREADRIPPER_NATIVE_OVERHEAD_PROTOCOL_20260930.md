# Prospective Native Point-Collector Slowdown Control

Preparation only. No allocation, launch authorization, passing review or
controlled result is created by this protocol. Timing remains deferred while
unrelated scientific work uses the local Threadripper. No DGX use or workload
interruption is authorized.

## Question And Design

The completed 22380 fixed-duration calibration established sampled accounting
and cadence, not slowdown: its work stops after 30 seconds irrespective of
how much computation completes. Do not rerun it to answer the slowdown question.

Compare the one-second native point collector against a boundary-only control
on **completed native inference**, not a sleeping or duration-limited worker.
Derive 27 pairs from the retained local command plan: three methods, three
4/8/12-proteome sizes, three repeats. Each pair has two fresh native runs.
These 54 engineering tasks are additional to and separate from the unchanged
27 production identities. Their size is explicit; no immediate run is proposed
and no engineering outcome may be retroactively counted as production timing.

Keep input bytes, enumeration, executable/runtime, scientific settings and
CPU/RAM/timeout limits identical within each pair. Only fresh paths and the
collector arm differ. The builder reversibly checks the complete run object,
not only a subset of flags. Both arms use fresh tmpfs inputs, isolated native
TMP and JIT caches; preflight/hashing occurs outside native wall measurement.
Neither arm evicts system filesystem caches.

Parent method/size/repeat block order is preserved. Within each method/size,
the first two repeats have opposite arm orders; a SHA256 seed fixes the
third order prospectively. This is reproducible counterbalancing, not a claim
of perfect time-drift elimination or externally generated randomization.

## Arms And Common Conditions

- **Periodic:** the existing local collector: one-second native lineage,
  hierarchy, thread affinity, resource and root-context points. Finalization
  and raw receipts remain intact.
- **Boundary:** requires a new local implementation and native validation.
  Use the same native worker/gate, timeout, completion boundary and native wall
  clock. Retain pre/post native scope, placement and completion evidence but
  do not enumerate native task/thread/root context every second. A parent exit
  without verified subtree completion does not qualify as a valid control.
- **Both:** retain the same independent whole-host observation, environmental
  release review, sequential exclusive allocation and terminal audit. Do not
  turn off environmental safeguards to make the control faster.

Resources remain 32 native CPU IDs 0-31, 64 scheduler slots, 128 GiB and an
85,800-second native timeout. No hard 32-CPU quota or CPU exclusivity from
non-Slurm work is implied. Each run must have fresh, reviewed whole-run
environment evidence under a prospectively frozen policy. Common host
monitoring cost is not isolated by this contrast: this measures incremental
native point-collection slowdown, not total cost of every safeguard.

## Pair Audit And Engineering Budget

Independently validate scheduler/native terminal state, zero native exit,
no timeout, source/runtime/inputs, actual command, placement, environment,
native output formats and canonical same-method outputs before accepting a
pair. Group/pair fingerprints can reuse the existing output identity helper;
equivalent outputs are necessary but do not prove identical internal work.

Report the signed ratio `periodic wall / boundary wall - 1`. Retain negative
ratios. The engineering limits are <=0.10 for every pair and <=0.05 for the
median of all three valid pairs in each method/size cell. These are engineering
thresholds, not confidence bounds or a basis for subtracting overhead from
production measurements. Do not claim causality from a shared-host pair.

Record all 54 prescribed outcomes, including failed, timed-out, contaminated
and unrun tasks. Stop after an invalid attempt; do not retry selected pairs,
discard slow results, compute partial-cell medians or replace missing with zero.
Incomplete panels have no complete-panel passing decision. Any prospective
amendment must retain this protocol and all earlier attempts.

## Remaining Before Execution

Implement/test the boundary control and its independent replay; bind both arms
to stable source/runtime recipes; integrate actual environment handoff and
complete pair auditing; establish a verified quiet window. The existing source
and protocol pins remain historical evidence, not automatic current-source
approval. Preparation does not clear these gates or establish publication
readiness. The production panel also needs its own final readiness review.
