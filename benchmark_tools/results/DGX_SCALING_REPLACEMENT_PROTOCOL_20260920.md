# Prospective Replacement Scaling Specification

## Scope And Status

Preserve the 27 original method/size/repeat identities, nested input bytes,
native enumeration, scientific settings and method order from the frozen
September 17 DGX plan. This is a separate prospective replacement panel,
not selective replacement of unfavorable observations. The original panel
remains descriptive evidence. No historical resource measurement is promoted.
Preparation does not authorize execution or establish environmental validity.

Use fresh destinations under `scaling_root_context_v1`, with no search reuse,
output reuse, global cache flushing, inference tuning or overhead subtraction.
Keep high sensitivity, satellite_v2 and full OrthoFinder 3.1.5, 4/8/12 complete
proteomes and three repeats per method/size. Every intended outcome remains
in the inventory even if failed, timed out, invalid or unrun.

## Measurement And Execution

Use the native root-context collector validated in 22021 and paired in 22022,
with one-second requested interval and the existing 30-second host-snapshot
cadence. Preserve actual read windows and gaps; requests are not guarantees
of cadence. Retain native-step cgroup memory/CPU, GNU-time accounting, raw
lineage/root-context reports, CPU flags, memory/I/O pressure and output
validation as distinct evidence. The collector's four-proteome overhead test
does not supply a universal bound at larger sizes.

Each run uses exclusive 20-CPU/96-GiB access on spark-7ff0, partition spark,
with a 24-hour Slurm limit and 23h50m native timeout. Execute sequentially,
without requeue. Hold one bounded submitting SSH session for each allocation
and capture its terminal scheduler record locally. Use remote/local wait
bounds 86,520/86,550 seconds and a ten-second remote termination grace.
Queue delays consume these bounds: an observation timeout is not terminal
evidence and never authorizes another submission of the same run.

Input preparation, copying/hashing, output validation, conversion and scoring
stay outside the native inference timer and receive separate recorded stage
boundaries. Inference includes database construction, CLI startup, all native
children and final native output writing. No checkpoint duration is inferred
by subtracting historical times. Check pinned source/runtime/input/order
identity before and after each run. A successful process exit does not prove
output correctness or resource comparability.

## Environmental Policy Required Before Launch

The enabled failing Samwise user service is a known background workload.
Its temporary stop/runtime-mask requires user approval; preserve and restore
its prior configuration if approved. If not approved, do not silently stop it
or relabel its activity as absent. Freeze the actual service policy before
execution. No unrelated service, job or host setting may be changed implicitly.

Record the permitted baseline services and their configurations, allocation
and host identities, and pre/post hardware state. Preserve whole-run workload
observations and bounded service logs. Document visibility gaps, unsupported
GPU telemetry, device-I/O attribution limits, non-atomic reads and thermal/
memory-bandwidth uncertainty. Absence of a sampled foreign process is not
proof of zero short-lived outside work. No arbitrary new numerical isolation
threshold is introduced by this specification.

Known unapproved concurrent workloads, policy/configuration drift or missing
required environmental evidence prevent controlled-comparison admission.
Native CPU/PSI flags remain visible but are not themselves causal labels or
automatic grounds to exclude a method. In particular, do not require zero
native memory/I/O stalls or subtract native PSI from host PSI. Native work can
cause its own stalls; outcome-dependent exclusions would bias comparison.

## Failures And Reporting

Native failures/timeouts retain consumed resources and exact status. Continue
to the next prescribed identity only after terminal state and evidence capture
are verified and the environment remains eligible. Infrastructure/provenance
failure or observed policy breach pauses further submissions; remaining
identities are explicitly unrun. Do not retry or replace runs automatically.
Any replacement experiment needs a separately recorded prospective rule.

Show all runs, memory and wall time separately, input counts, failures, CPU
flags and environmental dispositions. Complete three-repeat method/size
summaries require three eligible, output-valid runs; do not report a partial
median as a complete result. Missing/ineligible measurements stay visible.
Do not select fastest repeats, pool ARM/x86 timings, correct for measured
overhead, or extrapolate a universal scaling law from one nested series.

The environment policy, tested executor, terminal/session capture, full
source recipe and independent audit are still required. This specification
does not resolve those gates or narrow the publication goal to timing alone.
