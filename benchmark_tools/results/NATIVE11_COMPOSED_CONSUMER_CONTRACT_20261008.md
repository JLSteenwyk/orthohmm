# Native11 Composed Review Consumer Contract

`native11_composed_review_binding.py` is the explicit new-type acceptance API
for prospective conversion/scoring. It never translates the composed report
into an original review or changes frozen original consumers.

Acceptance requires native23985 and composed producer24034 both successfully
terminal, exact native identity/request/plan/amendment, successful resource,
environment and output gates, truthful postterminal-runtime lineage, and the
declared shared-host scopes. It preserves false original inventory equality,
original ordinary-review success, next-identity authorization and scoring
admission. Producer24034 must match its2CPU128GiB envelope and retained single
submission/release/source bindings. All retained review, raw evidence, original
semantic-output and recipe/source records are checked. The output is a distinct
binding tuple with explicit composed provenance, not an ordinary-schema shim.

Focused fixtures verify the new-type gate, reject altered identities/claims and
nonterminal/wrong-envelope producers, and confirm that the original ordinary
converter still rejects a valid new-type report. These are not production
end-to-end admission tests; producer24034 is still running at preparation.
The production binding and subsequent conversion/scoring cannot be exercised
until the actual complete review exists and independent readback confirms it.

Remaining implementation is a separate compatible pair converter and assessment
runner/admitter using the unchanged pair-materialization, ownership, mapping,
coverage and six-endpoint kernels. Preserve prediction semantics: native11 has
reconciliation off, so predictions are cross-species group-derived clique pairs,
not native phylogenetic pairs or graph edges. No new accuracy metric or baseline
rerun is authorized by this compatibility API. History-dependent native12 needs
its own compatible operational contract; this API does not authorize that launch.
